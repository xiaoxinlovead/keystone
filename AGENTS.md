# Keystone repo guide for agents

## Project

RISC-V secure enclave framework (Keystone). Monorepo with git submodules.

## Architecture

| Directory | Role |
|---|---|
| `sm/` | Security Monitor (OpenSBI-based, M-mode firmware) |
| `sdk/` | C/C++ library for writing enclaves (cross-compiled for RISC-V) |
| `runtime/` | Eyrie runtime (enclave payload, modular cmake options) |
| `linux-keystone-driver/` | Loadable kernel module for enclave ioctl |
| `linux/`, `buildroot/`, `qemu/` | Upstream mirror submodules |
| `bootrom/` | BootROM binary |
| `sm/opensbi/` | OpenSBI submodule |
| `patches/` | Per-submodule patches applied at build time |

Entrypoints:
- Root `CMakeLists.txt` orchestrates full-system build (QEMU + bootrom + SM + Linux + driver + image)
- `sdk/CMakeLists.txt` standalone SDK build (cross-compiled for RISC-V)
- `runtime/CMakeLists.txt` standalone runtime build (requires SDK installed)

## Required env vars

- `$RISCV` — RISC-V toolchain install prefix (fatal error if unset at cmake configure)
- `$KEYSTONE_SDK_DIR` — installed SDK path (runtime build errors if unset)

Both set by `source ./source.sh`.

## Setup

```bash
./fast-setup.sh           # downloads prebuilt toolchain, clones submodules, builds SDK
source ./source.sh        # sets RISCV, PATH, KEYSTONE_SDK_DIR (auto-generated by setup)
```

- For RV32: `BITS=32 ./fast-setup.sh` before building with `-DRISCV32=y`
- `fast-setup.sh` sets `git config submodule.riscv-gnu-toolchain.update none` (skips the huge toolchain submodule)
- `newfast-setup.sh` skips toolchain download (expects `$RISCV` pre-installed) and does NOT auto-clone linux/qemu (they must exist)
- `source.sh` is generated by setup scripts — don't version it

## Build

```bash
source ./source.sh
mkdir build64 && cd build64
cmake ..                                        # configure all components
make -j$(nproc)                                 # builds: qemu, bootrom, linux, driver, sm, buildroot, image
```

Individual component targets: `make qemu`, `make linux`, `make sm`, `make driver`, `make buildroot`, `make bootrom`.

Enclave examples are `EXCLUDE_FROM_ALL` — build with `make tests` or `make run-tests`.

### Build dependency chain

```
run-tests → tests + tools + image + fw_jump.bin
image     → buildroot + sm
sm        → linux + opensbi patches
linux     → buildroot (initramfs mode) or standalone
tests     → examples (sdk subdirectory)
```

### Build variants (pass to `cmake`)

- RV32: `-DRISCV32=y`
- SiFive FU540: `-DLINUX_SIFIVE=y -DSM_PLATFORM=sifive/fu540`
- CVA6: `-DSM_PLATFORM=cva6` (configs: `conf/linux64-cva6-defconfig`, `conf/riscv64_cva6_defconfig`)
- Debug: `-DCMAKE_BUILD_TYPE=Debug` or `RelWithDebInfo`

## Build system quirks

Top-level cmake uses `add_custom_target`/`add_custom_command` (NOT `add_subdirectory`) for QEMU, Linux, buildroot, SM, driver, bootrom — it orchestrates external builds, not native cmake targets.

Patches in `patches/<submodule>/` are applied automatically via `add_patch()` macro during cmake build. Exception: Linux kernel patches in `patches/linux/` are **commented out** in CMakeLists.txt (lines 190-196) — not auto-applied.

**Dual toolchain**: SM and bootrom use `riscv{BITS}-unknown-elf-` (bare-metal), while SDK, Linux, and buildroot use `riscv{BITS}-unknown-linux-gnu-` (Linux userspace). Don't mix them up.

**QEMU** builds both `riscv{BITS}-softmmu` (system emulation) and `riscv{BITS}-linux-user` (user-mode, needed for SM unit tests).

Linux kernel configs are in `conf/linux{32,64}{,-sifive,-cva6}-defconfig`. Buildroot configs in `conf/qemu_riscv{32,64}_virt_defconfig`.

All build artifacts go to the cmake binary dir (`build64/`). The build is fully out-of-source.

## Runtime build options

Pass to runtime cmake: `-DFREEMEM=on -DPAGING=on -DPAGE_CRYPTO=on -DPAGE_HASH=on -DLINUX_SYSCALL=on -DIO_SYSCALL=on -DNET_SYSCALL=on`

These set `-DUSE_<NAME>` compile flags. The `options_log` target logs which are enabled.

CI tests these runtime option combinations: Default, FREEMEM, LINUX_SYSCALL+FREEMEM, PAGING, PAGE_CRYPTO, PAGE_HASH, PAGE_CRYPTO+PAGE_HASH.

## Known build issues

### Linux kernel: `rseq_execve` / `rseq_syscall` redefinition

Both `include/linux/sched.h` and `include/linux/rseq.h` define the same `static inline` stub functions. Fix: remove duplicate definitions from `sched.h` (the `#else` block for `rseq_execve` and `rseq_syscall`).

### SDK: missing `stdint.h` / `cstdint` with newer toolchains

Files using `uintptr_t` / `uint8_t` may lack the required include. Add `#include <stdint.h>` (C) or `#include <cstdint>` (C++) to:
- `sdk/include/host/keystone_user.h`
- `sdk/src/verifier/json11.cpp`

## Testing

| Scope | Command | Notes |
|---|---|---|
| QEMU integration | `make run-tests` (from build dir) | boots QEMU, SSH in, runs `.ke` packages, diffs vs `tests/test-qemu.expected.log` |
| SDK unit tests | `make check` (from sdk/build dir) | runs on **host** (x86 gcc/g++, NOT cross-compiler); requires GoogleTest (`sdk/tests/scripts/setup_test.sh`) |
| Runtime tests | `make test` (from runtime/build dir) | cmocka-based; requires `git submodule update --init test/cmocka` first |
| SM tests | `cmake .. && make test` (from `sm/tests/build`) | cmocka, cross-compiled, runs in QEMU user-mode (`qemu-riscv{32,64}`) |

QEMU SSH port is auto-assigned (3000-5999). `test-qemu.sh` handles upload/execution. On OpenSSH >= 9, passes `-O` flag to `scp`.

## Code format

SDK and runtime each have `.clang-format` and `make format` target (SDK also runs cpplint).

## Branch conventions

- `master`: public releases, always "healthy" (docs + tests pass)
- `dev`: development, PR target for contributions (submodule PRs first, then keystone PR)
- No direct commits to `master`
